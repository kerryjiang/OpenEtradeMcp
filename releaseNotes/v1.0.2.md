# OpenEtradeMcp v1.0.2

Release Date: 2026-04-18

## What's New

### E*TRADE API Schema Fixes

Fixed the OpenAPI specification (`etrade-api.yaml`) to match E*TRADE's actual API request format, resolving failures when placing, previewing, canceling, or modifying orders.

#### Request Body Envelope Wrapping

E*TRADE requires POST/PUT request bodies to be wrapped in a top-level property named after the request type. Added envelope schemas to match this convention:

- `PreviewOrderRequestEnvelope` — wraps `PreviewOrderRequest` (used by `previewOrder` and `previewChangeOrder`)
- `PlaceOrderRequestEnvelope` — wraps `PlaceOrderRequest` (used by `placeOrder` and `placeChangeOrder`)
- `CancelOrderRequestEnvelope` — wraps `CancelOrderRequest` (used by `cancelOrder`)

For example, a preview order request is now correctly serialized as:
```json
{
  "PreviewOrderRequest": {
    "orderType": "EQ",
    "clientOrderId": "...",
    "Order": [...]
  }
}
```

#### Missing `accountId` in `OrderDetailRequest`

Added the missing `accountId` property to `OrderDetailRequest`. Without this field, the E*TRADE API could not identify which account the order belongs to.

#### PascalCase Property Names for Complex Types

E*TRADE uses PascalCase (uppercase first letter) for properties that are object or array types. Updated the following property names across order request schemas:

- `PreviewOrderRequest`: `order` → `Order`, added `clientOrderId` as required
- `PlaceOrderRequest`: `order` → `Order`, `previewIds` → `PreviewIds`
- `OrderDetailRequest`: `instrument` → `Instrument`, added `accountId`, `allOrNone`, `priceType`, `orderTerm`, `Instrument`, and `marketSession` as required fields
- `InstrumentRequest`: `product` → `Product`, added `Product`, `orderAction`, `quantityType`, and `quantity` as required fields
